## ADDED Requirements

### Requirement: Query factory through the shared load-or-build decision

The runtime fixture SHALL obtain its `QueryFactory` through `QueryModelLoadOrBuild` using the loaded model's digests and the persisted query model locator, in `build` and in strict `load` mode, and SHALL NOT extract and build the query model by hand.

#### Scenario: Strict load restores the generated query model
- **GIVEN** generated model files including `<name>-query.model` in `target/generated-test-sources/model/`
- **WHEN** the fixture runs with mode `load`
- **THEN** the `QueryFactory` is restored from the query file
- **AND** a missing, stale or unresolvable file fails `prepare(...)` instead of falling back

#### Scenario: Build mode never opens the query file
- **GIVEN** the same generated model files
- **WHEN** the fixture runs with mode `build`
- **THEN** the `QueryFactory` is built from the ASM, measure and expression models
- **AND** the query file is not opened

#### Scenario: Full suite in both modes
- **GIVEN** the jsl-itest models
- **WHEN** the jsl-itest suite runs in strict `load` and in `build`
- **THEN** the suite passes in both modes with no fallback

## MODIFIED Requirements

### Requirement: Model loading and schema generation

The runtime fixture SHALL load JSL models from generated test sources, including the `<name>-query.model` file written by the workflow, and apply database schema via Liquibase.

#### Scenario: Model preparation
- **GIVEN** generated model files exist in `target/generated-test-sources/model/`
- **WHEN** `prepare(modelName, datasourceFixture)` is called
- **THEN** the ASM model, RDBMS model, and Liquibase changeset are loaded and the database schema is applied

#### Scenario: Generated models include the query file
- **GIVEN** a jsl-itest model generated by `judo-tatami-jsl-workflow-maven-plugin`
- **WHEN** the generated model directory is listed
- **THEN** it contains `<name>-query.model` next to the ASM, measure and expression models
